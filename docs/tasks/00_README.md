# spatial-cad-mcp - task packages: closing the CAD coverage gaps (DXF / IFC)

Prepared from a coverage review of the current `main` (commit `116e562`).
Goal: give every coding agent (Gemini on Drive, then Vibe porting to the repo)
self-contained, convention-compliant task specs.

## Workflow rules (binding - see root AGENTS.md and docs/)

1. One branch per task: `task/<nn>-<slug>`; one PR per task; CI must stay green
   (`uv run pytest`, `ruff check .` + `ruff format --check .`, `cargo check/clippy/test --workspace`).
2. Every tool answers with the standard envelope (`ok`/`data`/`meta` or `ok:false` +
   `error{code,message,retryable}`); error codes are stable snake_case; lists are
   paginated with hard cap 200 (`meta.limit_clamped_to`); include `duration_ms`.
3. All paths resolve inside `MCP_CAD_WORKSPACE_ROOT` via the sandbox crate/module;
   `..`, absolute-outside and symlink escapes are rejected (`path_traversal`,
   `path_outside_workspace`).
4. Read-only tools never write. Mutating tools NEVER modify inputs: they write a
   NEW file under `<workspace>/outputs/` (name collision = `output_exists`) and
   return a structured diff (counts before/after, output path).
5. Never pull raw geometry or full entity trees into an agent context: summaries
   with counts, paginated slices, truncated long values with a marker.
6. Update docs with every tool: root `AGENTS.md` tool index, the package README,
   `docs/tool-design.md` if envelope vocabulary changes.
7. Commits are AI-assisted and signed with the agent trailer, e.g.:
   ```
   Generated by Mistral Vibe.
   Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
   ```
8. Data policy: code, tests and synthetic fixtures only; tests build inputs in
   `tmp_path`; no real project data, no absolute paths in examples.
